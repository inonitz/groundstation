1. Thread Architecture (Point 1.A & Last Point 1)

Decouple vision, control, and VLM.

    Thread 1 (Depth / 30Hz+): Reads depth map. Checks center-frame distance. If an obstacle is < 50cm, it asserts an atomic m_emergencyStop flag and wakes the VLM via std::condition_variable.

    Thread 2 (YOLO Seg / 25Hz): Updates bounding boxes. Fuses with latest depth map.

    Thread 3 (VLM / Async): Sleeps. Wakes only via std::condition_variable::notify_one().

2. The 20Hz Control Loop (Points 1.B & 1.C)

You are wrong about pushing "finished" commands. PX4 Offboard mode requires continuous, uninterrupted setpoints to stay alive.
Do not send commands sequentially once. You must stream the current active command's parameters at 20Hz. If m_currTask is GO XYZ, you publish XYZ 20 times a second. If the queue is empty, you publish Hover (0 velocity) 20 times a second.
Source for Offboard Control: https://docs.px4.io/main/en/ros/ros2_offboard_control.html
3. Event-Driven VLM (Point 1.D)

Kill the 5-second timer. The VLM only runs when told.
Trigger conditions:

    Queue is Empty: Needs new instructions.

    REASSESS Command: The queue reached a planned stop to look around.

    Emergency Override: Depth thread saw a wall and threw the atomic flag.

4. Task Completion Math (Point 1.E & Last Point 2)

Do not use the VLM to check status. It takes 2 seconds. The drone will crash.

    If ROTATE X: Check current yaw vs target yaw. If < 5 degrees, mark FINISHED_SUCCESS.
