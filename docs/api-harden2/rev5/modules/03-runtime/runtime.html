runtime: Die's four hand-offs, the one supervisor thread, ROS2, the start-up check (rev5, revised 2026-10-16)

The document is runtime.md; the header is runtime.h. Every hand-off is a line with the thread that runs it.

How to read it

  1. A, Die. Any thread calls Die; the first wins and later callers park. Every registered function runs on its own short-lived thread, joined against its step's deadline, so a function stuck in a C call is left behind. Step 1 sends the stop and the manual switch itself, on its own connection, 400 ms each; it never goes through the emergency thread, which may be the thread inside Die. Step 2 is one direct POST to the phone's speech, no FIFO, no chat line. Step 3 flushes the recorder, each on its own thread. Step 4 runs on the Die thread: it takes the launch lock, sets the stopping flag, sends SIGINT through the pidfd to each child without a stop already sent, a second SIGINT to llama-server after 2 s, waits on every pidfd with one deadline, never reaps, then kills the late ones and logs them. Then _exit. Worst case 16.5 s.
  2. B, the supervisor. One thread. It sleeps in one poll on every child's pidfd and on the command pipe, with a timeout at the earliest of three deadlines. A readable pidfd means that child exited: it unregisters the pidfd, reaps that pid through its Popen (never waitpid(-1)), closes the pidfd, and applies the policy: a stop sent means DOWN and no policy; a planned restart relaunches; a crash counts and relaunches after 1, 2, 4 s. The supervisor owns every process: the app creates it with every spec, and it launches them all here, under the launch lock. Commands from other threads arrive on the pipe: a planned restart, the quit. Each row is one atomic store of an immutable pair; the main thread reads six per frame.
  3. C, ROS2. One context. A listener per topic on its own node and executor thread; it stamps the message and hands it on. Measured: a 1080p frame listener stalls the main thread up to 17 ms; that number belongs to the frame source's review.
  4. D, the start-up check. Runs before any package import. A miss dies at once; nothing is registered for a hand-over yet, and nothing is airborne.
