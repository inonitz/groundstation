01

The verdict — two solutions, very different footing

Everything the drone does was proven inside isolated tests, never yet as one live system. SITL can fly the full stack today. The Tello can sense and think, but cannot reliably move to a place until SLAM gives it a position.

SITL (PX4 · Gazebo)

Showcase-ready

Position comes free from PX4 EKF2, so every motion law works. This is the reliable demo.

  • ✓GO · ROTATE · APPROACH · ORBIT · SEARCH all fly — odometry-accurate
  • ✓Safety reflex, boundary, battery failsafe, manual override
  • ✓Real Qwen3-VL planning from live YOLO-seg + depth
  • ~Never run as a full system — only per-feature test rigs

DJI Tello (real hardware)

Gated on SLAM

Telemetry, camera, and planning are live on the drone. Horizontal position is not — the SDK reports none.

  • ✓Takeoff · hover · yaw · altitude · land · camera stream
  • ✓Battery failsafe, manual override, VLM planning off the feed
  • ✕GO / APPROACH / ORBIT / SEARCH — drift without X,Y
  • ✕Return-to-start — needs a metric origin it doesn't have

Capability matrix

Flight core

Done

20 Hz loop; GO, ROTATE, TAKEOFF, LAND, STOP, ORBIT, SEARCH. SPSC queue + backpressure.

APPROACH

Done

Dead-reckon travel budget, motion-gate impact reject, standoff 2.5 m, dead-reckon finish on target loss.

Safety / failsafe

Done

Interrupt reflex, velocity-scaled + free-space boundary, storm escalation, battery RTH/land, override.

VLM planner

Done

Event-driven wake, async off the control thread, tolerant plan extraction, dynamic state+history prompt.

Perception

Perf miss

Vision lib + FMU two-rate integration ship. Seg ~1.5–2×, depth ~3.5–4.6× over target on this CPU.

Backends

Tello partial

GenericBackend + PX4 done. Tello telemetry/camera live; stick-to-m/s cal + wind correction open.

SLAM / pose

Scaffold

Monocular stella_vslam compiles & links, vocab + config present, pose code written — not brought up.

Objective termination

Design only

No deterministic "done" detector. Layered plan: reassess verdict + human voice + battery floor.

Observability

Missing

No way to see the VLM's input frame or the depth map. Debugging is log-archaeology today.

Runtime config

Deferred

Tuning constants are compile-time constexpr; one binary can't serve SITL and Tello without a rebuild (9.14).

05

Validation & tooling — what's still blind

No live sandbox

Build it

scripts/sandbox/run.sh <world> <objective> — launch the real binaries with no canned plan, drive the VLM live, hit manual interrupts, record a bag for reproducible edge cases.

Human-debuggee gap

Observability

Publish the annotated camera frame + a depth colormap to a topic, view in Foxglove/rviz, and log the VLM prompt+response each cycle. Today you fly blind to what the model sees.

tmux capture fragility

Quick fix

Tests scrape tmux scrollback, which drops events under load. Tee FMU stdout to a file so nothing is lost — stops the "false FAIL" reruns.

Objective termination

Design only

Layered: a completion verdict in every reassess, a spoken "done, land" backstop, and the battery floor. Prompt work first, then the voice wire.

06

The path from here

NOW

Land the two commits

Feature (spec-1 + spec-2 + this session's fixes) and governance, separately. Unlocks the FMU.

PARALLEL

Track 1 ∥ Track 2

Operator calibrates the Tello camera on the ground. Overseer brings stella_vslam up in SITL and confirms slam/pose tracks. Neither touches the FMU.

PHASE 2

Wire pose · voice · termination

Feed slam/pose into the FMU as Tello position + return-to-start. Route ASR to an interrupt with a [USER] prompt block. Add the completion verdict.

PHASE 2b

Build the sandbox + observability

Live full-system launch, depth/VLM-view viewer, log-to-file capture. This is what makes the SITL demos and every future debug session tractable.

PHASE 3

Hardware, next Tello window

Calibrated config on the real drone, stella tuned, 10–15 min flights, people clear. Fall back to the position-free demos if tracking is shaky.
