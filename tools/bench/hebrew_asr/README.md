# ASR round scorecard — Hebrew voice loop

Selects the ASR for the Hebrew voice loop. Two models compete: whisper-large-v3-turbo (ivrit-ai
fine-tune) and wav2vec2-xls-r-300m-lm-hebrew. Whisper is measured across two engines (whisper.cpp,
faster-whisper/CT2), four precisions, and CPU vs GPU. All numbers are on the FLEURS he_il test set.

## Reproduce

Prerequisites on this host:
- `whisper-cli` built at `build/release/shared/dji/bin/whisper-cli` (whisper.cpp, Vulkan).
- ivrit whisper GGML models at `/root/models/asr/ivrit_ai/whisper-large-v3-turbo/`.
- wav2vec2 + KenLM at `/root/models/asr/wav2vec2-xls-r-300m-lm-hebrew/`.

Then one command:

    bash run.sh                             # all 9 lanes, all 792 clips (~35 min on GPU)
    bash run.sh --n 30 --lanes fp16,w2v2    # quick subset
    bash run.sh --step stats                # re-print tables from existing results/

`run.sh` bootstraps a venv on first call, sets `HF_HOME` + the CUDA lib path faster-whisper needs,
and calls `asr_bench.py`. The FLEURS corpus and the CT2 model download themselves on first run.
Output: per-lane raw JSON in `results/`, and the WER / bootstrap-CI / latency / McNemar tables
printed to the terminal.

Layout:

| file | role |
|---|---|
| `asr_bench.py` | the whole benchmark in one file: corpus prep, the three lanes, scoring, stats, `main()` |
| `run.sh` | the one command: venv bootstrap + env + run |
| `results/` | raw per-clip JSON, one file per lane, plus `FINAL-summary.json` |
| `manifests/` | the FLEURS clip manifest (regenerated by `--step prep`) |

## Objective

Pick the ASR model, engine, and precision for the Hebrew voice loop. Primary metric: word error
rate (WER) on real Hebrew speech. Secondary: latency and CPU-vs-GPU feasibility. The owner decides.

## Setup

- Corpus: `google/fleurs`, config `he_il`, split `test`. 792 clips, 123.0 minutes, 13,536
  reference words. Clip duration p25/p50/p75/max = 6.4/8.5/11.4/29.9 s.
- Corpus noise (frame-RMS proxy, estimate): est-SNR p10/p50/p90 = 9.7/31.9/58.0 dB. General read
  speech, mostly clean, with a noisy tail. No wind, no controlled level.
- Models:
  - `ivrit-ai/whisper-large-v3-turbo` (~809M), run via whisper.cpp (GGML) and via
    faster-whisper/CTranslate2. Same weights in both engines.
  - `imvladikon/wav2vec2-xls-r-300m-lm-hebrew` (300M CTC, 2022), run through transformers with a
    pyctcdecode + KenLM 5-gram decoder (alpha 0.5, beta 1.5), and once without the LM.
- Decode: deterministic. whisper.cpp greedy (beam 1, best-of 1, temperature 0, no fallback).
  faster-whisper greedy (beam 1, temperature 0, no previous-text conditioning, VAD off).
  wav2vec2 CTC argmax, or KenLM beam. Determinism verified: identical output on repeat runs.
- Scoring: text lowercased (Latin only), punctuation stripped, niqqud removed, whitespace
  collapsed. WER and CER via jiwer over the same normalization for reference and hypothesis.
- Statistics: corpus WER with a clip-level bootstrap 95% interval (2000 resamples). Paired model
  comparison by exact McNemar on per-clip sentence-exact-match. Latency as percentiles over a
  50-clip subset, measured with the model resident (load time excluded).
- Hardware: RTX 5070 Laptop (8151 MiB), 32-thread CPU. whisper.cpp uses Vulkan; faster-whisper
  and wav2vec2 use CUDA (torch 2.11 + cu128). One model resident on the GPU at a time.

## Analysis

1. Whisper-turbo dominates wav2vec2 on general Hebrew: 18.72 vs 64.01 WER, non-overlapping
   intervals, McNemar p about 1e-47. wav2vec2 produces a fully correct sentence in 0.1% of clips.
2. The two whisper engines are statistically equivalent for the same weights: whisper.cpp fp16
   18.72 vs faster-whisper int8 19.03, McNemar p = 0.83. Engine choice is latency and deployment,
   not accuracy.
3. Quantization is free through q5_1: WER 18.72 to 18.79, intervals overlap. q4_0 costs a small
   but paired-significant amount: WER 19.59, McNemar vs fp16 p = 0.017. CT2 int8 equals whisper.cpp
   q5_1 (McNemar p = 0.26).
4. GPU latency: whisper.cpp q4_0 and q5_1 are fastest (p50 222 and 231 ms). CT2 int8 is 260 ms.
   CT2 fp16 is 408 ms. whisper.cpp fp16 is 318 ms. Quantization cuts whisper.cpp latency about 30%.
5. CPU is not viable for the live loop: faster-whisper int8 on CPU is p50 3351 ms, about 15x the
   GPU figure. Its 17.68 WER is a 150-clip subset with a wide interval and is not comparable to the
   792-clip lanes. CPU is a batch option only.
6. The KenLM helps wav2vec2 WER (64.01 vs 72.03) but not enough to compete. CER rises with the LM
   (37.67 vs 33.28): the LM trades character-close fragments for real dictionary words.
7. Scope limit: FLEURS he_il is general read speech. It ranks capability. It does not test the
   drone-command domain, military phraseology, or wind. wav2vec2's hypothesized advantages
   (in-domain command LM, noise robustness, no hallucination on silence) are untested here.

## Conclusions and open decisions

- Recommended model: whisper-large-v3-turbo (ivrit-ai). It is the clear winner on Hebrew ASR.
- Recommended engine and precision: whisper.cpp q5_1 gives the lowest GPU latency at full accuracy
  and is already built into the project. faster-whisper int8 is an equivalent-accuracy alternative
  with easier Python integration and built-in VAD, at about 30 ms more latency.
- Quantization floor: q5_1. Use q4_0 only if about 10 ms matters; it carries a small accuracy cost.
- CPU deployment for whisper-turbo is ruled out for the real-time loop.
- wav2vec2 is not competitive on general Hebrew. Revisit only with in-domain command audio and a
  command-corpus KenLM.
- Open (needs the team recordings): in-domain command WER, military phraseology survival, and wind
  robustness. These decide whether wav2vec2's constrained-grammar path has any real advantage.
